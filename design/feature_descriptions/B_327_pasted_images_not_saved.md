The markdown editor accepts pasting images into the editor. While the editor remains open, this looks good. however, on cards, when you close and open the card again, the image itself is gone and it now says something like: `<img height="472" width="410" alt="pasted image" src="pasted-image-1c4cf12a-2a6c-4e32-b42b-134214d25ad3.png" />` So the image is not saved I suppose. we need to find a way to make this work. is it possible to 'inline' the image as a base64 string? or any other options?

## Current state

Pasting already transports the image bytes as base64, saves them as a separate image file beside the card, and inserts a relative Markdown image reference. The image asset itself is not lost.

MDXEditor keeps an unmodified image as Markdown. After the user resizes it, MDXEditor serializes the dimensions as an HTML `<img>` tag because standard Markdown has no image-size syntax. `plainMarkdownPlugin` intentionally imports every HTML node as literal text, overriding MDXEditor's HTML image importer. The resized image therefore remains visible until the editor is reopened, then appears as its literal `<img>` source.

Relative image loading and preview already work through `resolveCardImageSource`. Inlining the image as a data URI is unnecessary and would make card files and Git diffs substantially larger.

## implementation details

- Keep image resizing enabled and keep general HTML processing suppressed.
- Extend the HTML import handling in `plain_markdown_realm_plugin.ts` with a narrow path for image HTML generated by MDXEditor.
- Recognize only a single `<img>` element with a non-empty `src` and the supported attributes `src`, `alt`, `title`, `width`, and `height`. Treat malformed tags and tags with other attributes as literal HTML.
- Create an MDXEditor image node from the recognized tag. Read `src` with `getAttribute('src')` so a relative card asset path is not converted into an absolute browser URL. Preserve the optional text fields and numeric dimensions.
- Keep the existing literal-text import behavior for every other HTML node.
- Do not change image persistence, card saving, preview resolution, release handling, or archive handling.
- Add a real-editor regression test that loads a resized image tag, saves it, reopens it, and verifies that it remains an image with the same source and dimensions. Retain coverage proving that unrelated HTML remains literal text.

## acceptance criteria

- Pasting an image saves the image asset beside the card and displays it in the editor.
- Resizing an image, saving the card, closing it, and reopening it displays the image at the saved dimensions instead of showing a literal `<img>` tag.
- The relative image source remains unchanged and resolves through the existing card image preview path.
- Images that were not resized continue to serialize as ordinary Markdown image references.
- Existing supported resized-image tags become editable images when their cards are reopened.
- Malformed image tags, image tags with unsupported attributes, and all non-image HTML remain literal text.
- No image data is inlined into the card Markdown.
- Focused real-editor tests cover resized-image reopen behavior and unchanged literal HTML behavior.
