The react tab of the config dialog needs to be removed:

* startup splash has no real value, it should always be on, it should not be a configurable value
* delete integrated card branch, delete released card branches, auto commit delay should move to the 'project' tab, 'git' group
* include project agent in activity release should not be an option, remove, this value should always be 'true', so remove from config, consumers of config values should always presume this is true.

## Current state

The config dialog's tab list comes from `CONFIG_SECTIONS` in `app/src/services/config/config_entries.ts`, today `react` ("React app"), `project` and `desktop`. `getVisibleSections` in `app/src/components/config/config_page.tsx` walks that list and appends the Markdown tab right after the `react` section and the Sentry tab right after the `project` section, so the Markdown tab exists today only because a `react` section exists. `getActiveSection` falls back to the first visible section when the hash names no known section, so the React app tab is also the default tab.

Every config entry carries two independent fields: `section`, which decides the tab it renders on, and `source` (`react` | `desktop` | `project`), which decides where the value is stored. Five entries currently use `section: 'react'` and `source: 'react'`:

* `react.showStartupSplash` (default `true`, editable) — read by `app/src/app.tsx` through `readStartupSplashPreference()` in `app/src/services/config/config_persistence.ts`. That helper reads localStorage directly because `App` needs the value before `configService.init` runs; `app.tsx` renders `<StartupSplash />` only while `bootstrap.phase === 'starting'` and the preference is on.
* `react.deleteBranchAfterIntegration` (default `false`, `editable: false`) — seeds the delete-branch checkbox of the worktree integration dialog in `app/src/components/worktree_selector.tsx:58`, and is written back on every toggle at `worktree_selector.tsx:286`.
* `react.deleteBranchesAfterRelease` (default `false`, `editable: false`) — seeds `defaultSelectAll` for the branch list of `CompleteReleaseDialog`, read at `app/src/components/shell/project/use_project_toolbar_menu_actions.ts:89` and written back at line 391.
* `react.includeProjectActivityInRelease` (default `false`, `editable: false`) — seeds the "Include project agent activity" checkbox of `CompleteReleaseDialog`, read at `use_project_toolbar_menu_actions.ts:90` and written back at line 395. The checkbox value travels as the third argument of `onCompleteRelease` into `projectSessionService.completeRelease` and then `releaseOperations.completeRelease` (`app/src/services/release_operations.ts:162`), where it decides whether `loadArchivedProjectActivity` runs and the project agent activity is copied into the release folder.
* `react.autoCommitDelayMs` (default 30000, editable slider, 1000–120000 step 1000) — read once in the `DataService` constructor (`app/src/services/data/data_service.ts:223`) and passed to `new CommitBatcher(this.cards, delayMs)`. `CommitBatcher.delayMs` (`app/src/data/commit_batcher.ts:112`) is `readonly` and is only consulted in `window.setTimeout(..., this.delayMs)` at line 162, so today the delay is frozen at app start.

`editable: false` does not hide an entry from the React app tab: `ReactConfigSection` passes every `section === 'react'` entry to `ConfigSectionLayout`, which renders them all. The flag is only consulted by `ProjectConfigSection`, when it decides which ungrouped project entries to render. So the three branch/release booleans are visible in the React app tab today, and are simultaneously the remembered state of dialog checkboxes.

Storage differs per source. React-source values live in one localStorage blob under `md2.reactConfig` (`REACT_CONFIG_STORAGE_KEY`), written by `writeStoredReactValues` from `LOCAL_STORAGE_KEYS`, which is itself derived from `source === 'react'`. `configService.setReactPreference` writes one value straight to that blob, outside the config dialog draft; `configService.saveDraft` writes the blob again for the dialog path. Project-source values live in the project's config JSON file: `ConfigService.loadProjectConfig` resets every key in `PROJECT_KEYS` to its default and then merges each field the file actually defined, `readProjectConfig` maps the value map onto the `ProjectConfig` interface in `app/src/data/data_types.ts`, and each storage service serializes that whole object with `JSON.stringify` (see `app/src/services/github/github_project_config_storage.ts:26`), so a field added to `ProjectConfig` round-trips without a format change. `ConfigService.saveDraft` runs `validateValue` over `PROJECT_KEYS`, which already handles `type: 'number'` with `min`/`max`. `ConfigPage.handleSaveClick` calls `configService.saveProjectConfig()` when `hasDraftChangesForSource('project')` reported a change. `setConversationPinned` is the existing precedent for writing one project config value immediately from outside the dialog draft: it merges the value, awaits the persistence boundary, then updates `values` and, when one is open, the draft.

`ProjectConfigSection` already renders named groups from the `PROJECT_CONFIG_GROUPS` constant added by F\_370; the Git group currently holds `project.diffCommand` and `project.pushMode`.

Tests that touch this area: `app/src/App.test.tsx:107-116` (splash shown by default, skipped when the stored preference is `false`), `config_page.test.tsx` (the "Startup splash" switch, the `React app` region, and its `#/config/react` tab href), `main_window.test.tsx:303-311`, plus `config_persistence.service.test.ts` and `config_service.service.test.ts`, which both use `react.showStartupSplash` as their sample react-source value.

## implementation details

Decisions taken for this feature: the three moved values become real project config, stored per project in the project config file, so two projects can differ; there is no migration of existing `md2.reactConfig` values, each project simply starts at the entry default; and the dialog checkboxes stay where they are and keep writing their value back, so the Git group shows and edits the same remembered default.

* Delete `react.showStartupSplash` from `ConfigValueTypes` and `CONFIG_ENTRIES`. Delete `readStartupSplashPreference` from `config_persistence.ts` and its re-export from `config_service.ts`. In `app.tsx`, drop `showStartupSplash` and render `<StartupSplash />` unconditionally while `bootstrap.phase === 'starting'`.
* Rename the three moved keys into the `project` namespace, keeping their labels, descriptions, defaults and slider bounds, and set both `section: 'project'` and `source: 'project'` on each:Set `editable: true` on all three, since they now render as fields the user edits directly. Add the three keys to `PROJECT_KEYS`, add the three fields to the `ProjectConfig` interface in `data_types.ts`, map them in `readProjectConfig`, and add the matching `if (projectConfig?.<field> !== undefined)` merge lines in `ConfigService.loadProjectConfig`. A project config file written before this feature defines none of them, so each falls back to the entry default that the reset loop already applied — that is the intended no-migration behaviour.
  * `react.deleteBranchAfterIntegration` → `project.deleteBranchAfterIntegration`
  * `react.deleteBranchesAfterRelease` → `project.deleteBranchesAfterRelease`
  * `react.autoCommitDelayMs` → `project.autoCommitDelayMs`
* Add the three keys to the Git group in `PROJECT_CONFIG_GROUPS` (`project_config_section.tsx`), after `project.diffCommand` and `project.pushMode`, and widen the group description so it covers branch cleanup and the auto-commit delay rather than only the diff command and push mode.
* Delete `react.includeProjectActivityInRelease` entirely and make inclusion unconditional. Remove the `includeProjectActivity` parameter from `releaseOperations.completeRelease` and `projectSessionService.completeRelease`, so `loadArchivedProjectActivity` always runs and the archived project activity is always part of the release. Remove the third argument from `onCompleteRelease`, and remove the `defaultIncludeProjectActivity` and `onIncludeProjectActivityChange` props, the `includeProjectActivity` state, the change handler and the "Include project agent activity" `FormControlLabel` from `CompleteReleaseDialog`. Remove `releaseIncludeProjectActivityDefault` and `setReleaseIncludeProjectActivityDefault` from `use_project_toolbar_menu_actions.ts`, and the matching prop wiring at the dialog's call site.
* Add `ConfigService.setProjectPreference<K extends ProjectConfigKey>(key, value)` for the two dialog write-backs, shaped like the existing `setConversationPinned`: validate the value, merge it into `values`, persist through `withProjectConfigSave` → `requireProjectConfigPersistence().saveProjectConfig(readProjectConfig(nextValues))`, then commit it to `values`, mirror it into `draftValues` when a draft is open, and dispatch `changed`. It must be a no-op that does not throw when no project is loaded, because the dialogs that call it can only be open with a project open but the type does not enforce that. Point `worktree_selector.tsx:286` and `use_project_toolbar_menu_actions.ts:391` at it with the new keys, and update their `useConfigValueOrFallback` reads at `worktree_selector.tsx:58` and `use_project_toolbar_menu_actions.ts:89` to the new keys.
* Make the auto-commit delay follow the project. `CommitBatcher` freezes the delay at construction, which was harmless for a global localStorage value but is wrong for a per-project one: the value is still at its default when `DataService` builds the batcher, before any project config is loaded. Replace the `delayMs` constructor argument with a `delayMsProvider: () => number` (defaulting to `() => AUTO_COMMIT_DELAY_MS`) and call it at line 162, where the timeout is scheduled, so each scheduled flush uses the currently loaded project's value. In `data_service.ts`, pass `() => configService.get('project.autoCommitDelayMs')`. An already-scheduled timeout keeps the delay it was scheduled with; only the next scheduled flush picks up a new value.
* Remove the React app tab and the now-dead react source. Delete `app/src/components/config/react_config_section.tsx`, plus its import and render branch in `config_page.tsx`. Drop `{ id: 'react', label: 'React app' }` from `CONFIG_SECTIONS`. No entry uses `source: 'react'` after this feature, so also remove `'react'` from the `ConfigSource` union, delete `LOCAL_STORAGE_KEYS`, `REACT_CONFIG_STORAGE_KEY`, `readStoredReactValues`, `writeStoredReactValues` and `mergeStoredReactValues` from `config_persistence.ts`, and delete `setReactPreference`, the `ReactConfigKey` type, the `mergeStoredReactValues` call in `init` and the `writeStoredReactValues` call in `saveDraft` from `config_service.ts`. Leave whatever `md2.reactConfig` blob is already in a user's localStorage alone; nothing reads it any more.
* Reattach the Markdown tab in `getVisibleSections`. It currently hangs off the `react` section; hang it off `project` instead, after the Sentry tab, so the visible order becomes Project, Sentry, Markdown, Desktop and the default tab (the `getActiveSection` fallback to `sections[0]`) becomes Project rather than Markdown. An old `#/config/react` link no longer matches a section and therefore lands on the Project tab through that same fallback; the stale example in `design/releases/0_0_3/F_69_config_in_dialog.md` is release history and stays as written.
* Tests: drop the `skips the startup splash when the preference is disabled` case in `App.test.tsx` and keep the default-on case; replace the React-app-tab cases in `config_page.test.tsx` with ones asserting the tab list is Project, Sentry, Markdown, Desktop, that no "React app" tab and no "Startup splash" switch exist, and that the Git group holds diff command, push mode, both branch settings and the auto-commit delay slider; update the splash-switch case in `main_window.test.tsx`; move the react-source cases in `config_persistence.service.test.ts` and `config_service.service.test.ts` onto project-source keys, and add one asserting that `setProjectPreference` persists through the project config persistence boundary and updates an open draft. Add a `complete_release_dialog` case asserting the include-activity checkbox is gone and that a release always archives the project activity. Verify with `npm run typecheck` and the config, release, worktree and app vitest suites.

## acceptance criteria

* The config dialog has no "React app" tab; its tabs are Project, Sentry, Markdown and Desktop, in that order, and Project is the tab shown when config opens without a section in the hash. Opening `#/config/react` shows the Project tab instead of an empty dialog.
* The startup splash always shows while the last project is restored, both on a fresh install and on an install whose stored preference was `false`; no config field controls it and no code reads the preference.
* The project tab's Git group holds, in order: diff command, push mode, delete integrated card branch, delete released card branches, auto commit delay. Each is editable there, and the group description mentions branch cleanup and the auto-commit delay.
* Those three values are stored in the project config file, not in localStorage: saving them from the config dialog writes the project config, and two projects opened in turn each show their own values.
* A project config file written before this feature still loads, and the three new fields fall back to their defaults (delete branch after integration `false`, delete branches after release `false`, auto commit delay 30000 ms) rather than to whatever was in `md2.reactConfig`.
* Toggling the delete-branch checkbox in the worktree integration dialog, or the select-all-branches checkbox in the complete-release dialog, still remembers the choice: it is written to the open project's config immediately, and the config dialog's Git group shows the new value the next time it is opened.
* Changing the auto commit delay in the config dialog, or opening a project whose config sets a different delay, changes the delay used by the next scheduled auto-commit, with no app restart.
* The complete-release dialog has no "Include project agent activity" checkbox, and every completed release archives the project agent activity into the release folder.
* No config entry uses the `react` source and no code writes `md2.reactConfig`; an existing `md2.reactConfig` blob in localStorage is left untouched and ignored.
* `npm run typecheck` passes and the config, release, worktree and app test suites pass.
